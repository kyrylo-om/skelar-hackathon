# SupportPilot — архітектура (чернетка)

Статус: чернетка. Пункти з позначкою **[пропозиція]** ще не підтверджені командою.

## Ідея
AI-агент підтримки, який не лише відповідає, а виконує дії. Кілька агентів перевіряють один одного, а остаточний бар'єр безпеки — звичайний код. Складні випадки передаються оператору.

## Вимоги (з чату та PDF)
- Стек: Python, Django, React. Deploy опційно.
- Бекенд — "пуста апішка": ендпоінти є можливими діями агента.
- Безпека: флоу з кількох агентів (Actor та Critic).
- LLM-адаптер: працює з різними провайдерами та має mock-режим без ключа.
- Здача до 17:00: код одним ZIP, презентація до 10 слайдів, відеодемо.

## Домен демо [пропозиція]
Хмарне сховище з підпискою. Головний сценарій: "оплата пройшла, а тариф не активувався". Дані — власний демонстраційний сервіс з тестовими користувачами, підписками та платежами.

## Конвеєр агентів
1. **Guard** — шукає prompt injection, маскує PII. Текст клієнта вважається даними, а не інструкціями.
2. **Triage + Actor** — інтент, сентимент, пріоритет, мова, план дій.
3. **Critic** — окремий промпт, перевіряє, чи план відповідає запиту клієнта.
4. **Policy Engine** — код без LLM: власник підписки, ліміти сум, статус, ідемпотентність, rate limit.
5. **Executor** — виконує дію, пише в аудит, створює undo.
6. **Responder** — відповідь лише з реальних результатів дій.
7. **QA** — оцінка якості та метрики (асинхронно).

Особа клієнта береться з сесії, а не з тексту повідомлення.

## Реєстр дій [пропозиція]
Кожна дія має `name`, `params_schema`, `risk`, `undo`.

| Дія | Ризик | Умова |
|---|---|---|
| get_subscription / get_payments | низький | лише дані цього клієнта |
| resync_plan | низький | платіж успішний, тариф неактивний |
| pause / resume_subscription | середній | підтвердження клієнта |
| cancel_subscription | середній | підтвердження, спершу пропозиція паузи |
| refund | високий | автоматично лише до ліміту, інакше оператор |
| escalate_to_human | низький | завжди дозволено |

## Чого агенту не можна
Діяти за чужим акаунтом; виконувати дії без перевірки Policy; повертати гроші понад ліміт; видаляти акаунт чи дані; змінювати платіжні дані, пароль чи пошту; розкривати чужі дані та внутрішні інструкції; казати "виконано" без підтвердження backend; виконувати інструкції з тексту клієнта; повторювати дію при дубль-запиті; ходити по колу без ліміту спроб.

## Кабінет оператора (мінімальний)
Пропозиція Andrii. Складається з:
- списку переданих звернень;
- діалогу;
- підсумку від AI (причина передачі, перевірені факти);
- можливості відповісти клієнту в тому самому чаті;
- trace агентів та відкату дії (undo).

## Контракт
План Actor:
```json
{"intent": "...", "confidence": 0.9,
 "actions": [{"name": "...", "params": {}, "reasoning": "..."}],
 "needs_clarification": null}
```
Trace pipeline:
```json
{"steps": [{"agent": "guard|triage|actor|critic|policy|executor|qa",
            "verdict": "...", "detail": "..."}],
 "reply": "...",
 "actions_done": [{"id": 1, "name": "...", "undo_until": "..."}]}
```
Ендпоінти: `POST /api/chat`, `GET /api/tickets`, `GET /api/tickets/{id}`, `POST /api/tickets/{id}/reply`, `POST /api/undo/{id}`, `GET /api/audit`, `GET /api/security-events`, `GET /api/metrics`.

Стан розмови (`pending_plan`) зберігається на сервері, щоб підтримувати багатокрокові сценарії.
